# Wild encounter port - what the time-window mapping costs

Generated by `.claude/encounter_losses.py`. Johto/Kanto only; Hoenn was
never read.

## The mapping

`OW_TIMES_OF_DAY` is `GEN_LATEST`, and this tree ships a **customised**
Gen 8 block in `include/constants/rtc.h`:

| Window | Hours | Served before | Served after |
|---|---|---|---|
| `TIME_MORNING` | 06:00-09:59 | this tree's Day table | the fork's Day table |
| `TIME_DAY` | 10:00-17:59 | this tree's Day table | the fork's Day table |
| `TIME_EVENING` | 18:00-18:59 | this tree's Day table | **the fork's Night table** |
| `TIME_NIGHT` | 19:00-05:59 | this tree's Night table | the fork's Night table |

Morning+Day is 06:00-17:59 and Evening+Night is 18:00-05:59, which is
exactly the fork's own split (`hours >= 6 && hours <= 17` is day, in
`pokemonHnS/src/script.c`). So the mapping is exact, not an approximation.

**Neither tree contains a single Morning or Evening encounter table.**
Scanning every `base_label` in both files: this tree has 149 `_Day` and 91
`_Night`, the fork has 68 `Day` and 230 `Night` (all of those on Hoenn
`_CDay`/`_CNight` variants), and zero `Morning` or `Evening` on either
side. So no Morning- or Evening-specific data existed to be lost. What
follows is what changes for those windows because the *table serving them*
changed.

## Caveats

**Alternate Spawns is dropped.** The fork indexes encounters as
`i += VAR_TIME_BASED_ENCOUNTER - 1` over 1..4, which is
`{default, tx_Mode_AlternateSpawns} x {Day, Night}` - four *consecutive*
entries per map. This tree's four slots are Morning/Day/Evening/Night, a
different axis that happens to be the same width. The offsets +2/+3 are
therefore not portable, and `VAR_TIME_BASED_ENCOUNTER` is dead here
anyway: `src/script.c` still sets it, but nothing reads it. In scope only
`MAP_MT_SILVER_SNOW` has all four entries, and its +2/+3 pair was already
unreachable here, since `GetCurrentMapWildMonHeaderId` returns the first
header matching a map.

**One engine change was required.** `src/overworld.c` had an `IS_HNS`
block that set `FLAG_DAY_POKEMON`/`FLAG_NIGHT_POKEMON` for overworld
sprites, commented "TIME_MORNING and TIME_EVENING both fall back to the
Day table" and switching only at `TIME_NIGHT` (19:00). With Evening now
serving the Night roster, sprites would have swapped an hour after the
encounters did, so the condition now includes `TIME_EVENING`.

**`SPECIES_NONE` is excluded** from every count below - it is a padding
slot, not a catchable encounter.

## Adding Morning / Evening tables later

Both are already live times - `gTimeOfDay` really does become
`TIME_MORNING` and `TIME_EVENING`, and the lighting uses them. Only the
encounter *tables* are absent, so they fall back to Day.

To give either its own encounters, add entries to
`src/data/wild_encounters.json` with `_Morning` / `_Evening` on the base
label, beside the existing `_Day` and `_Night`:

```json
{ "map": "MAP_ROUTE29_HNS", "base_label": "gRoute29_hns_Morning", ... }
```

The generator keys off the suffix, groups labels sharing a stem into one
header, and fills the matching `encounterTypes[TIME_*]` slot. No code
change is needed - `OW_TIME_OF_DAY_ENCOUNTERS` is already `TRUE`.

Two things to watch:

- **`src/overworld.c`'s `IS_HNS` block** swaps the overworld Pokemon
  sprites at `TIME_NIGHT` only, on the stated assumption that Morning and
  Evening both fall back to Day. Give Evening a Night-like table and the
  sprites will lag the encounters by an hour unless that condition gains
  `|| gTimeOfDay == TIME_EVENING`.
- **Do not put a time word in the map's own name.** The generator scans
  the label for Morning/Day/Evening/Night in enum order and takes the
  last match, so `gMtSilver_SnowNight_hns_Day` resolves to *Night*. That
  entry already exists and is already mis-slotted; it is harmless only
  because it is a duplicate header the map lookup never reaches.
